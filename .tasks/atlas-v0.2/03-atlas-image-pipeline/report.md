## Deviations from suggested approach

- Used direct authenticated route handlers and native `fetch` multipart calls instead of adding the OpenAI SDK. This keeps the provider boundary dependency-free and matches the required Image API endpoint.
- Kept generation execution synchronous per route request after first persisting the generating snapshot. The persisted state remains honest and reloadable; a background worker is outside v0.2 scope.
- Real paid/provider calls were not made automatically. Controlled providers exercised all completion/error UI states, while the required medium/high paid comparison remains intentionally human-owned.

## Blockers

- `OPENAI_API_KEY` is not configured in the ordinary local shell. The user must configure it privately and confirm GPT Image 2 organization access before the real gate.
- Human selection of the production `ATLAS_IMAGE_QUALITY` default is intentionally unresolved until identical medium/high outputs are compared.

## Human gate

1. Configure `OPENAI_API_KEY` locally and verify GPT Image 2 access; do not paste the key into chat.
2. Confirm the workspace feels like an append-only user direction log with no assistant replies.
3. Record voice direction, stop, edit the transcript in the composer, and confirm it remains unsaved until Add Direction.
4. Use the same source, ordered references, and direction entries for one `medium` and one `high` generation.
5. Compare quality, latency, and geometry drift, then choose the production `ATLAS_IMAGE_QUALITY` default.
6. Reload and confirm the winning output remains in Bunny, File Images, history, result, and detail.
7. Continue editing the winner, add a new direction, generate again, and confirm lineage plus prior history remain intact.
8. Exercise blocked/retryable recovery and explicitly approve Milestone 3 if it feels correct.
